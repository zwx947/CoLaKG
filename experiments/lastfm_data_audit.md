## 结论

**可以将现有实验作为“原作者公开代码及数据版本下的可追溯复现基线”，足以继续后续模型研究；不必为凑齐论文数字而补交互或重新划分。**本次未发现交互重复、训练测试交叉污染、ID 越界或明显排名评估实现错误。此结论限定于已核对的公开资产与实现，不等于证明所有预生成语义内容都不存在信息泄漏。

尚不能称为论文全部实验协议的严格复现：论文的 86,608 条交互与公开版本 71,294 条之差仍未查明；本次为单种子且记录测试曲线最大值，论文表 2 则报告五次运行平均值。后续比较应固定当前数据、映射、语义资产及评估口径，并保留这些限制。

## 3. 预处理溯源：已证实与未证实

**已证实：**公开 `user_artists.dat` 有 92,834 行且用户—艺人对无重复，涉及 1892 用户、17632 艺人。仅保留 `user_map.txt` 和 `item_map.txt` 键中同时存在的原始用户与艺人，再按两表映射，得到的 71,294 对交互集合与当前 train/test 并集**完全相等**，无额外或遗漏交互。这证明现有文件形成自洽的数据链路，不证明映射表的生成规则。

作者 `data_preprocess/lastfm-2k.ipynb` 读取已有 `item_map.txt`，生成艺人标签知识图谱和物品 LLM 输入；其中标签集合化及 KG 三元组 `dropna` 不等于推荐交互去重。该 notebook **没有**生成映射表、执行交互筛选、划分或导出 train/test 的代码，不能从它还原论文 86,608 的计算过程。

**尚未证实：**论文与公开文件之间的 15,314 条差额究竟来自其他数据版本、统计阶段或表格笔误。不能称其为“被过滤／被去重／验证集记录”：当前 split 和公开原始 user_artists 都没有重复，且缺少论文计数到公开文件的完整转换链路。92,834 到现有映射范围的集合差为 21,540，它也不是论文差额 15,314 的解释。

## 4. ID 与语义嵌入

- user_map 的 1859 个键、item_map 的 2813 个键均映射至连续且无重复的 0 起始编号；物品提示中 **2813/2813** 个艺人名称与原始艺人及 item_map 一致。
- 物品输入与响应 JSON 覆盖 ID 0–2812，用户响应 JSON 覆盖 0–1858，值均为非空文本。公开嵌入脚本按 `json[str(i)]` 排序文本，因此其生成约定是第 i 行对应 ID i，不依赖 JSON 键插入顺序。
- 物品／用户嵌入为 float32，形状分别 **[2813,1024]／[1859,1024]**，全部有限且无全零行；两份文件与 main **逐字节一致**，映射和响应文本也与 main 一致（文本仅换行可能不同）。嵌入 SHA-256 分别为 `8d826d30a8bac4a25fcde9e98dc4f7116da6fda954f05dae764de86634e64fab`、`8ce9c4d833a9f17937478c76ccdff0ea1214b5b347e4ff2232562a63dc593215`。
- 已核实结构对应与公开资产来源；未重新编码文本验证每行向量数值。公开 LastFM notebook 不含完整用户画像构造，本地也无 llm_input_user.json，**不能额外证明预生成用户语义只使用训练历史**；这属于溯源限制，不是已发现污染的证据。

改变用户／物品编号或范围会使嵌入行语义错位或越界；即使保持编号，仅改变交互划分，也可能让既有用户画像与新训练历史不一致，甚至引入新测试历史泄漏。因此当前交互、映射和嵌入必须作为整体冻结，不能直接补足论文差额。

## 5. 评估检查、边界与后续资格

静态检查原始 Loader、Procedure.Test 和指标函数：图与训练正例来自 train.txt，测试真值来自 test.txt；排名遍历全部物品并屏蔽该用户训练正例，Recall 分母和 NDCG 理想排序长度取自实际测试真值。结合交集为零、测试用户非空和 ID 有效，未发现明显的本地数据污染或评估口径实现错误。本轮未调用 Test、未加载任何模型 checkpoint、未重新选择模型；仅在 CPU 读取现有语义张量。
