# 中心—邻居逐维融合失败分析

## 范围与结论

分析固定实验direct-test-content_neighbor_fusion-s2020-20261030-025447-df2704，代码9b28b63、结果7ec14d7。读取已记录曲线，并在CPU加载本次best-protocol和final冻结checkpoint做机制诊断；没有optimizer、参数更新、测试集排名重算、方法筛选或新训练。checkpoint加载仅供分析，不作为新实验初始化。

现有证据支持：该配置很早就偏向中心，随后形成大量饱和的逐维选择，未获得预期的推荐收益。证据不能证明所有自适应融合无效，也不能证明饱和是性能下降的唯一原因。

## 1. 偏向中心出现在早期

已有评估日志中的平均邻居门控：

|完成轮数|0|5|20|100|500|1300（最佳）|2000|
|---|---:|---:|---:|---:|---:|---:|---:|
|均值|0.498542|0.053163|0.048567|0.042391|0.040986|0.027908|0.026921|

因此不能仅归结为2000轮后期过拟合。早期中间checkpoint没有保留，无法事后恢复第5轮的真实梯度或判断何时开始不可逆饱和。

## 2. 饱和是真实现象，但不能把平均系数当贡献率

使用同一训练图缓存、原语义资产和相同Top10重建CPU模型，严格载入已校验的本次checkpoint。最佳点CPU门控均值0.0279084258，与GPU日志0.0279084239一致。

|诊断|最佳1300轮|最终2000轮|
|---|---:|---:|
|物品×维度门控小于0.01的比例|96.31%|96.58%|
|门控大于0.99的比例|2.01%|2.07%|
|平均门控小于0.001的维度数（共64）|24|26|
|门控logit中位数|-28.12|-24.12|
|sigmoid导数中位数|3.97e-13|1.28e-11|

大部分坐标对logit变化已非常不敏感，但还存在少数有较大邻居权重的坐标。全体物品的加权邻居项范数/加权中心项范数分别约0.299、0.318；这个范数比也不是推荐性能贡献率。因此不能说邻居完全消失，或把平均系数0.028解释成只贡献2.8%。

## 3. 排序梯度仍存在，不能归咎于正则把门控压死

从原train抽取固定1024条正例，为各用户排除全部已知训练正例后抽负例。对冻结模型做一次训练模式前后向诊断，不执行优化器更新；这不是重放历史训练步，也不能代表所有batch。

最佳模型第一层门控权重的BPR梯度范数约1.72e-3，带1e-4系数的L2梯度约3.84e-6；第二层分别约1.62e-3和2.11e-6。最终模型同样有非零排序梯度。整体门控参数并未失去所有学习信号，剩余梯度可能集中于少数未饱和坐标。

训练日志中最佳轮门控正则对总损失贡献约1.04e-4，原六向量正则贡献约0.02295，BPR约0.02620。不能仅看正则系数就认定是新增门控L2过强，也不能从一次冻结梯度测量倒推出早期原因。

## 4. dropout和融合尺度是需要正视的耦合

原dropout_i=0.6、dropout_u=0.2、dropout_n=0.6；当前门控看到的是dropout和ELU之后的消息。用同一冻结模型、三个固定随机种子，只改变诊断前向中的dropout开关：

|模式|最佳门控均值|最终门控均值|
|---|---:|---:|
|评估（无dropout）|0.02791|0.02692|
|原训练dropout全部启用|0.01937|0.01851|
|只启用输入dropout|0.02510|0.02471|
|只启用邻居dropout|0.02249|0.02101|

这些是机制探针，不是新训练设置；没有在这些变体上计算测试指标。结果表明训练噪声会进一步影响门控选择，但关闭dropout后的冻结模型仍然明显饱和，不能宣称已找到单一根因，不能据此直接降低dropout追成绩。

另一个确定的结构事实：z=x+g*(m-x)。降低g不仅减少邻居项，还会提高中心项系数。原中心系数固定0.5，g趋近0时中心系数接近1；这同时改变信息比例与表示尺度。最佳模型未加权邻居消息/中心表示的逐物品范数比均值约0.562，两路也不是等幅信号。门控输入做LN，并没有对实际融合value做尺度校准。因此“学到哪个信息更可靠”与“学到对排序优化更有利的尺度/噪声路径”不能等同。

## 5. 对设计与下一步的判断

这轮将“信息是否有用”落实为逐维竞争门控，允许模型几乎跳过大多数邻居坐标；功能检查证明它能计算、收梯度和更新，却没有事先证明这种竞争能够学到有益互补。这是设计风险，不是已发现的代码索引错误。

不建议原样重跑、盲扫门控温度、提高正则，或凭“平均0.5更平衡”强迫权重回到0.5。主结果最佳NDCG@20=0.3425138673，相对原始-1.3878%、相对父模型-1.4771%，仍按原主口径保留，不更改选轮方式。

更值得继续推演此前第一项“中心条件的消息内容转换”：先研究同一邻居向不同中心提供哪些特征，再处理融合。已有非对称注意力学习邻居相对权重，内容转换学习传递什么，二者职责不同。相对本次竞争门控，这能直接检验消息内容适配，避免把融合权重当可靠性标签。是否保留固定融合、采用残差或做尺度校准，需要具体设计与对照；不先宣布任何结构必然有效，也不自动叠加A。

另一条可检验的假设是把用于决策的稳定信息与用于训练正则化的随机消息区分开。当前探针仅支持需要考虑这种区分，不能据此承诺改进。下一轮应选择明确假设并事前固定配置，同时记录早期门控/消息梯度和尺度，不等训练结束后才发现路径退化。

本轮到分析为止，没有启动后续实验。
